# Между строк

Windows-приложение для чтения и публикации историй в формате переписки.

## Читателю

Запусти `BetweenLines-Setup-1.0.0.exe`. Установщик создаст ярлык «Между строк» без прав администратора. Открой главу. Кнопки **Вбок** и **Вниз** переключают режим чтения. В режиме «Вбок» работают стрелки, PageUp/PageDown и горизонтальный свайп. Приложение запоминает страницу.

Новые главы проверяются при открытии и раз в минуту. Кнопка **Обновить главы** проверяет их вручную. Загруженные главы доступны без интернета. Для первой загрузки и обновлений интернет нужен. Для чтения аккаунт не требуется.

## Автору

Открой **Редактор**. Слева — список глав и кнопка **+**. Название главы редактируется сверху. В центре — реплики, справа — предпросмотр.

1. Выбирай отправителя и пиши сообщения. Кнопки внизу добавляют реплику от выбранного участника.
2. По умолчанию на странице 7 сообщений. Число можно изменить. Ножницы у сообщения начинают с него новую страницу — так можно закончить предыдущую нужной фразой. Стрелки меняют порядок сообщений.
3. В **Участники и вид** настрой имена, цвета и PNG/JPEG/WebP-аватарки. Аватарки можно показывать сверху, рядом с репликами или в обоих местах. Картинки обрезаются по центру в квадрат и уменьшаются до 256 × 256.
4. В **Открытие главы** можно выбрать дату и время. До этого момента читатель увидит конверт и таймер; в открытом приложении глава появится автоматически. Для проверки нажми **Открыть** над предпросмотром.
5. Нажми **Опубликовать**. Если эта глава уже опубликована, её версия обновится; новая глава добавится в библиотеку. Изменения появятся у читателя после проверки обновлений. Кэш GitHub иногда добавляет несколько минут задержки.

Незавершённый текст автоматически сохраняется на этом компьютере. Отдельного раздела черновиков нет. **Сохранить файл** создаёт переносимую копию всех глав, **Импорт истории** возвращает её в редактор. Импорт с совпадающим идентификатором заменяет соответствующую главу в редакторе. Удаление из редактора не удаляет опубликованную главу.

## Подключение публикации

Канал GitHub встроен в установщик. Автору нужно один раз открыть **Настройки** и нажать **Подключить автора**. Если вход сохранён в Git Credential Manager, ключ подхватится автоматически. Иначе можно использовать fine-grained GitHub token с доступом только к нужному репозиторию и разрешением `Contents: Read and write`. Ключ хранится через Windows DPAPI в профиле приложения и никогда не входит в установщик или истории. Читателю подключать автора не нужно.

Библиотека хранится в публичном `library.json`. Аватарки находятся внутри него; личных фотографий в демонстрации нет. Таймер ограничивает показ внутри приложения, а не доступ к публичным файлам. Он использует часы Windows; при неверном времени на компьютере момент открытия сместится.

## Обновление программы

При запуске установленная программа проверяет GitHub Releases. Новая версия предлагается пользователю: **Скачать**, затем **Установить и перезапустить**. Рабочий текст сохраняется перед перезапуском. Истории и прогресс находятся вне папки установки.

Чтобы выпустить новую версию исходников: увеличь `version` в `package.json` через `npm version patch`, отправь commit и тег `git push --follow-tags`. GitHub Actions соберёт Windows installer и файлы обновления. Автоматизация использует встроенный `GITHUB_TOKEN`. Репозиторий должен разрешать Actions. До первой автоматической сборки можно выполнить `npm run dist` и загрузить `.exe`, `.blockmap` и `latest.yml` в один GitHub Release.

Установщик не подписан коммерческим сертификатом: Windows может показать имя неизвестного издателя. Это ограничение этой сборки.

## Разработка

Node.js 24, Windows x64.

```powershell
npm ci
npm run build
npm start
```

Браузерный предпросмотр: `npm run dev`. Публикация и защищённое хранение ключа работают в Windows-приложении.

Проверки: `npm test`, `node tests/desktop.mjs`, `npm run dist`, `node scripts/verify-package.mjs`, `node scripts/verify-live.mjs`.

Для другого канала: `node scripts/channel.mjs GITHUB_LOGIN REPOSITORY`, затем пересобрать установщик. Локальные изменения канала — в настройках.

Данные приложения: `%APPDATA%/between-lines/`. `workspace.json` — рабочие главы, `library.json` — загруженная библиотека, `progress.json` — прогресс, `github.secret` — зашифрованный ключ. Резервную копию историй создавай кнопкой **Сохранить файл**.
